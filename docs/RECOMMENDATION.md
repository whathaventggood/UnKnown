# 可复现的反信息茧房推荐

策略版本 `unknown-rerank-1.0`，配置版本 `2026-11-17.1`。实现位于 `backend/app/recommendation/engine.py`，是没有数据库、网络和 LLM 依赖的纯 Python 模块。它只能估计内容可能陌生，不能判断用户掌握程度。

## 输入、召回和质量底线

业务服务在生成批次前读取当前档案的历史快照，将已入库主题作为候选。事件窗口、跳过有效期由服务层选择；算法不读取系统时钟，不读取未来事件。生成批次与实际曝光分离，生成结果不直接成为曝光。

同一稳定主题 ID 只保留一条；主题缺失标题、唯一统计主学科或可追溯来源时排除。URL 必须是 HTTP(S) 且不含凭据；生产调用者应从已核验来源库提供这些字段，URL 语法可用本身不证明网页内容真实。已标记重复或异常内容、质量代理小于 0.4、可学习性代理小于 0.25 的内容不会进入结果。来源、质量和可学习性底线永不因数量不足放宽。

质量 Q 使用入库时保存的来源与内容完整性代理分；缺失时采用显式默认 0.60，记录在 `feature_evidence.defaults`。它不等于事实正确率。仅对显式标记过时的热点材料折减质量，不把永久性主题的更新时间当真伪指标。

可学习性 L 考虑：是否存在入门摘要（0.35）、前置概念负担（0.35 × (1−负担)）、已确认可用例子（0.15）和有出处的熟悉概念桥梁（0.15）。负担缺失采用 0.5；未确认例子不给加分，不虚构置信度。源数据只说明存在摘要时，不能因此声称已完成 AI 教学解释。

## 评分和动态多样性

完全陌生及桥梁模式使用：

`S = 0.35 N + 0.25 Q + 0.20 D + 0.20 L`。

所有分项截断到 [0,1]。N 考虑主题和学科/细分领域是否有探索记录、近期实际曝光、用户显式已了解/完全陌生、熟悉学科、近期相近标题。探索强度通过新学科与细分领域奖励起作用，较高强度增加这些机会；不会直接提高题材难度。词相似采用英文词及中文双字 Jaccard，不依赖远程嵌入。

D 在每次加入主题前重新计算：

`D(x,A) = 0.65/(1+同主学科数) + 0.25/(1+同细分主题数) + 0.10×(1−与A中主题的最大文本相似度)`。

空集合时 D=1。唯一主学科用于覆盖和数量统计，关联标签不会增加覆盖数。每条结果保存加入前的主题列表，能够核对 D 的集合依赖。

暂时跳过只对该主题施加 0.12 的弱排名减分，不排除整个学科；有效期外服务层不传入该反馈。用户没有点击不会产生负反馈。

## 三种模式的实际差别

- **完全陌生**：按 N、Q、动态 D、L 贪心重排，优先未探索学科/细分主题和主动自述陌生的内容，最低质量与可学习性保持不变。
- **跨领域桥梁**：优先召回从熟悉主学科主题或显式已了解/已探索主题出发、有出处且语义有类型的连续路径，最多三跳。每跳保存方向、关系类型、解释、来源 URL。AI 类比不能成为可靠路径。路径必须连续、无环且终点匹配候选。可靠路径不足时扩展到完整候选池，逐条标记普通补充内容并返回 `BRIDGE_PATH_UNAVAILABLE` 或 `BRIDGE_POOL_EXPANDED`，不补造连线。
- **广域探索**：先按唯一主学科分层，使用固定种子打乱学科顺序并轮流取候选；层内按质量、可学习性和动态多样性选择。权重为 N=0.05、Q=0.35、D=0.40、L=0.20；N仅用于近期曝光重复抑制，不按兴趣、已了解或熟悉学科排序。启用历史时仍检查未探索机会约束。关闭 `broad_use_history` 时完全丢弃个人历史，既不抑制近期重复，也不检查个人未探索机会，结果中 `new_opportunities=null`，明确说明不能计算这一指标。

相同输入下三种模式有不同策略，但不要求任何输入都产生不同主题集合。

## 约束、可行性与降级

默认请求五条，目标至少四个主学科、每学科最多两条、至少两条属于未探索学科/细分主题且主题本身未探索，至少一条不是热点材料。

重排不是先任意贪心再截断。每一步使用按主学科和新机会/常青属性分组的小规模动态规划，检查剩余槽位是否仍能完成约束，避免抢先取走稀缺机会。

先考虑完整可用池（桥梁模式先扩池）。如果池中确实不存在常青内容，单独记录 `ONLY_NEWS_AVAILABLE`。其余不可行时依次降低新机会数量、主学科覆盖、放宽单学科上限；仍保持可追溯来源与质量/可学习性底线。候选总量不足就少返回，绝不复制主题补满。响应包括：请求/实际数量、原目标满足项、放宽项、原因代码、实际达成值和实际使用的门槛。

种子库无法提供某个学科时，任何推荐器都不能证明已覆盖该学科。算法不把知识库之外的未知范围纳入分母。

## 持久化与重放

结果带有 `strategy_version`、配置快照、随机种子、候选完整快照/指纹、历史前缀快照、每项特征与证据、最终约束情况。业务层将这些结果与档案、用户时区日期、模式、批号一起事务保存；重复读取当前批次不会重新运行算法。

```python
from app.recommendation import recommend

result = recommend(candidates, history, mode="unknown", count=5, seed=42)
replayed = recommend(
    result["candidate_snapshot"], result["history_snapshot"],
    mode=result["mode"], count=result["constraints"]["requested"],
    seed=result["seed"], config=result["config_snapshot"],
)
assert result == replayed
```

稳定种子并不意味着随机种子可替代证据。推荐理由只依据保存的真实特征模板生成，不调用 LLM 追加用户经历。
